Open `aperion-v0.4.0-rc2-standalone.html` in Edge at 100% zoom. No network needed.

| Time | Screen | Do | Point to make |
| --- | --- | --- | --- |

| 1:00 | Customer Records | Search "Northbridge"; open CRM-10452's details; select all six records | Six records across CRM, ERP, and Rebates; notes are evidence, not answers |
| 2:00 | Match & Compare | Show the Legal name and Tax identifier rows | Conflicts and missing values reported together; source system and verification date are context, not conflicts |
| 3:00 | Match & Compare | Put CRM-10814 in Group A and check | A similar name is not enough: the tax ID, legal name, and parent conflict, so the group is blocked. Then fix it: Keep separate |
| 4:00 | Match & Compare | Groups A and B; REB-33907 Hold for verification; check; submit proposals | Proposals go to governance review; duplicates refused; changes become revisions |

| 6:30 | Validation | Select identity evidence, write a rationale, watch the checklist complete; submit | "Submitted for Governance Review" — never an approval. Edit the rationale to show revalidation and history |
| 8:00 | Validation | Answer "Records not proposed" and the follow-up; Finish case | Explaining what you did not merge is part of the assessment |

Correct answers: `REGRESSION-CHECKLIST.md` section H. To demonstrate feedback on mistakes, finish once with an
error (for example, choose the ERP remittance address as Group A's operating address), then use
"Try the case again".

Fallback: if the standalone file will not open, unzip the modular package and open `site/index.html`.
